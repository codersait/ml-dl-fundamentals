Neural Networks

Neural networks are computational models inspired by biological neural networks. They consist of interconnected nodes (neurons) organized in layers that process information through weighted connections and activation functions.

Beginner Explanation

▼

Think of a neural network like your brain! Just as your brain has billions of neurons connected together, a neural network has artificial neurons (nodes) connected in layers.

Simple Analogy: Imagine you're learning to recognize cats in photos. Your brain doesn't recognize a cat all at once. Instead:

  • First, you notice basic features: edges, shapes, colors
  • Then, these combine to form patterns: eyes, ears, whiskers
  • Finally, all patterns together tell you: "This is a cat!"

A neural network works similarly! The input layer receives raw data (like pixel values from an image). Each hidden layer combines information from the previous layer to detect increasingly complex patterns. The output layer makes the final decision (like "cat" or "not cat").

Each connection between neurons has a weight - think of it as how important that connection is. During training, the network adjusts these weights to get better at recognizing patterns.

Step-by-Step: How Neural Networks Process Information

1 Input Layer Receives Data

The input layer is where data enters the network. Each neuron in this layer represents one feature of your input. For example, if you're processing a 28×28 pixel image, you'd have 784 input neurons (28 × 28 = 784), one for each pixel.

Input: [x₁, x₂, x₃, ..., xₙ]

Each xᵢ represents one input feature

2 Weighted Connections Multiply Inputs

Each connection between neurons has a weight (w). The input value is multiplied by its weight. Stronger weights mean that input has more influence on the next layer.

Weighted Input Calculation:
weighted_input = x₁ × w₁ + x₂ × w₂ + ... + xₙ × wₙ

Think of weights as volume controls - they determine how loud each input "speaks" to the next layer.

3 Summation and Bias Addition

All weighted inputs are summed together, and a bias term is added. The bias helps shift the activation function, allowing the neuron to fire even when inputs are small.

Sum with Bias:
sum = Σ(xᵢ × wᵢ) + b
Where b is the bias term. This sum is called the "pre-activation" value.
4 Activation Function Application

The activation function transforms the sum into the neuron's output. This introduces non-linearity, which is crucial - without it, multiple layers would be equivalent to a single layer!

Activation Function:
output = f(sum)
Common activation functions: ReLU (max(0, x)), Sigmoid (1/(1+e⁻ˣ)), Tanh (tanh(x))

The activation function decides whether and how strongly the neuron "fires" - similar to how a biological neuron either fires or doesn't fire.

5 Output Generation

The activated output becomes the input for the next layer. This process repeats through all hidden layers until reaching the output layer, which produces the final prediction.

Complete Forward Pass Formula:
y = f(Σ(wᵢ × xᵢ) + b)
This happens at every neuron, layer by layer, from input to output.

The output layer's values represent the network's prediction. For classification, these might be probabilities for each class (e.g., 0.8 for "cat", 0.2 for "dog").

Technical Deep-Dive

▼

Mathematical Formulation

Single Neuron Output:
$$y = f\left(\sum_{i=1}^{n} w_i x_i + b\right)$$
Where: xᵢ are inputs, wᵢ are weights, b is bias, f is activation function

Forward Propagation Algorithm

# Forward propagation through a neural network def forward_pass(inputs, weights, biases, activation): # Layer 1: Input to Hidden hidden_input = inputs @ weights[0] + biases[0] hidden_output = activation(hidden_input) # Layer 2: Hidden to Output output_input = hidden_output @ weights[1] + biases[1] output = activation(output_input) return output

Backpropagation Overview

Backpropagation is how neural networks learn. It calculates gradients (derivatives) of the loss function with respect to each weight, working backwards from the output layer to the input layer. The weights are then updated using gradient descent:

Weight Update Rule:
$$w_{new} = w_{old} - \alpha \frac{\partial L}{\partial w}$$
Where α is the learning rate and L is the loss function

Loss Functions

Mean Squared Error (MSE) - for regression:

$$MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2$$

Cross-Entropy Loss - for classification:

$$CE = -\sum_{i=1}^{n} y_i \log(\hat{y}_i)$$

Component Details

Weights: Learnable parameters that determine the strength of connections. Initialized randomly, then optimized during training.

Biases: Additional learnable parameters that shift the activation function, allowing neurons to fire even with zero input.

Layer Types:

  • Dense/Fully Connected: Every neuron connects to every neuron in next layer
  • Convolutional: Used for images, detects spatial patterns
  • Recurrent: Processes sequences, maintains memory of previous inputs

  • Input: 224×224×3 image (RGB pixels)
  • Hidden layers: Extract features (edges → shapes → objects)
  • Output: Probabilities for 1000 object classes

Attention Mechanism

Attention allows models to focus on relevant parts of the input when making predictions. It computes a weighted sum of values, where weights are determined by the compatibility between queries and keys.

Beginner Explanation

▼

Simple Analogy: When you read a sentence, you don't pay equal attention to every word. Your brain automatically focuses on the important words that help you understand the meaning.

For example, in the sentence "The cat sat on the mat", when processing the word "sat", your brain might pay more attention to "cat" (who sat?) and "mat" (where did it sit?) than to "the" (less important).

Attention in AI works similarly: The model learns which parts of the input are most relevant for making a prediction. Instead of treating all inputs equally, it assigns higher "attention weights" to more important parts.

Think of it like a spotlight on a stage - attention shines brighter on the actors (important information) and dimmer on the background (less relevant information).

Step-by-Step: How Attention Works

1 Create Query, Key, Value Vectors

Each input token is transformed into three vectors:

  • Query (Q): "What am I looking for?" - represents what information we need
  • Key (K): "What do I offer?" - represents what information each token provides
  • Value (V): "What is my content?" - the actual information content

Input: "The cat sat"

Each word → Q, K, V vectors

2 Compute Attention Scores (Q·K^T)

For each query, we calculate how well it matches each key by computing the dot product between the query and all keys. Higher scores mean better match.

Attention Score Calculation:
$$scores = Q \times K^T$$
This creates a matrix where each cell (i,j) represents how much token i should attend to token j

Think of this as asking: "How relevant is each word to what I'm currently processing?"

3 Scale and Apply Softmax Normalization

The scores are divided by √dₖ (where dₖ is the dimension of keys) to prevent extreme values, then softmax is applied to convert scores into probabilities that sum to 1.

Scaled and Normalized:
$$attention\_weights = softmax\left(\frac{QK^T}{\sqrt{d_k}}\right)$$
The scaling factor √dₖ prevents gradients from becoming too small in deep networks

After softmax, each row sums to 1.0 - these are the attention weights showing how much attention each token should pay to every other token.

4 Weighted Sum of Values

Multiply the attention weights by the Value vectors and sum them up. This creates a weighted combination where important tokens contribute more to the final output.

Final Attention Output:
$$Attention(Q,K,V) = softmax\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

The result is a new representation that incorporates information from all tokens, weighted by their relevance.

5 Generate Attention Output

The weighted sum becomes the attention output for that position. This output contains information from all input tokens, but emphasizes the most relevant ones.

Example: "The cat sat on the mat"

When processing "sat", the model might attend:

  • High attention to "cat" (0.4) - who performed the action
  • High attention to "mat" (0.3) - where the action happened
  • Low attention to "the" (0.05) - less informative

Technical Deep-Dive

▼

Scaled Dot-Product Attention

Complete Attention Formula:
$$Attention(Q, K, V) = softmax\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$
Where dₖ is the dimension of the key vectors. The scaling prevents the dot products from growing too large, which would push softmax into regions with extremely small gradients.

Multi-Head Attention

Instead of computing attention once, multi-head attention runs multiple attention mechanisms in parallel (called "heads"), each with different learned projections. This allows the model to attend to information from different representation subspaces.

Multi-Head Attention:
$$MultiHead(Q, K, V) = Concat(head_1, ..., head_h)W^O$$
$$where\ head_i = Attention(QW_i^Q, KW_i^K, VW_i^V)$$

Self-Attention vs Cross-Attention

Type Query Source Key/Value Source Use Case
Self-Attention Same sequence Same sequence Understanding relationships within one sequence
Cross-Attention Target sequence Source sequence Relating two different sequences (e.g., translation)

Why Attention Works

  • Long-range dependencies: Can directly connect distant tokens
  • Interpretability: Attention weights show what the model focuses on
  • Parallelization: All attention computations can happen simultaneously
  • Flexibility: Adapts to different input lengths without architecture changes

Examples & Use Cases

▼

Real-World Example: Machine Translation

When translating "The cat sat on the mat" to French:

  • When generating "chat" (cat), attention focuses on "cat" in English
  • When generating "tapis" (mat), attention focuses on "mat" in English
  • Attention weights show the alignment between source and target words

Code Example: Attention Implementation

def scaled_dot_product_attention(Q, K, V): # Compute attention scores scores = Q @ K.T / math.sqrt(K.shape[-1]) # Apply softmax to get attention weights attention_weights = softmax(scores, dim=-1) # Weighted sum of values output = attention_weights @ V return output, attention_weights

Transformer Architecture

Transformers revolutionized NLP by using self-attention mechanisms instead of recurrence. They consist of encoder and decoder stacks, each containing multiple layers of attention and feed-forward networks.

Beginner Explanation

▼

Assembly Line Analogy: Think of a transformer like a factory assembly line with two main sections:

  • Encoder (Reader): Processes and understands the input text, creating a rich representation of what it means
  • Decoder (Writer): Uses the encoder's understanding to generate the output text, word by word

Unlike older models that processed words one at a time (like reading left-to-right), transformers can look at ALL words simultaneously. It's like having eyes that can see the entire sentence at once, understanding how all words relate to each other.

Key Innovation: The transformer replaced sequential processing (which was slow) with parallel processing (which is fast), while still understanding word order and relationships through positional encoding.

Step-by-Step: Transformer Processing

1 Input Tokenization and Embedding

Text is broken into tokens (words or subwords) and each token is converted into a dense vector representation called an embedding. These embeddings capture semantic meaning - similar words have similar embeddings.

"Hello world" → [embedding₁, embedding₂]

Each token becomes a vector of numbers (typically 512 dimensions)

2 Add Positional Encoding

Since transformers process all tokens in parallel (unlike RNNs), they need a way to know word order. Positional encoding adds information about each token's position in the sequence.

Positional Encoding Formula:
$$PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$
$$PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$
Uses sinusoidal functions to encode position information that the model can learn to use
3 Encoder Stack Processing

The encoder consists of 6 identical layers (in the original transformer). Each layer has:

  • Multi-head self-attention: Each token attends to all tokens in the input
  • Feed-forward network: Processes each token independently
  • Layer normalization: Stabilizes training
  • Residual connections: Helps gradients flow through deep networks

Information flows through all 6 layers, with each layer refining the representation.

4 Decoder Receives Encoder Output

The decoder uses the encoder's final representation through cross-attention. This allows the decoder to "look" at the input while generating output. The decoder also uses masked self-attention to prevent looking at future tokens (since it generates left-to-right).

Cross-Attention Flow

Encoder output → Decoder cross-attention → Helps decoder understand what to generate

5 Decoder Generates Output Tokens

The decoder generates output tokens one at a time (autoregressively). At each step, it uses:

  • Previously generated tokens (through masked self-attention)
  • Encoder representation (through cross-attention)
  • Feed-forward processing

The final layer outputs probabilities over the vocabulary, and the token with highest probability is selected as the next output token.

Technical Deep-Dive

▼

Encoder Layer Components

1. Multi-Head Self-Attention

Allows each position to attend to all positions in the input sequence. Multiple heads allow attending to different types of relationships.

2. Feed-Forward Network (FFN)

FFN Formula:
$$FFN(x) = \max(0, xW_1 + b_1)W_2 + b_2$$
Two linear transformations with ReLU activation. Applied independently to each position.

3. Layer Normalization

LayerNorm Formula:
$$LayerNorm(x) = \gamma \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta$$
Normalizes across features (not batch). μ and σ are mean and std of x. γ and β are learnable parameters.

4. Residual Connections

Each sub-layer has a residual connection: output = LayerNorm(x + Sublayer(x)). This helps gradients flow through deep networks and enables training of very deep models.

Decoder Layer Components

Decoder layers have three sub-layers (instead of encoder's two):

  1. Masked Multi-Head Self-Attention: Can only attend to previous positions (mask prevents seeing future tokens)
  2. Multi-Head Cross-Attention: Attends to encoder output (connects encoder and decoder)
  3. Feed-Forward Network: Same as encoder

Positional Encoding Details

Positional encoding uses sinusoidal functions because they can extrapolate to sequence lengths longer than those seen during training. The frequencies decrease as dimensions increase, creating a unique pattern for each position.

Transformer vs RNN

Feature RNN Transformer
Processing Sequential (one token at a time) Parallel (all tokens simultaneously)
Long-range dependencies Difficult (gradient vanishing) Easy (direct attention)
Training speed Slow (sequential) Fast (parallelizable)
Memory O(n) sequential O(n²) attention matrix

Examples & Use Cases

▼

Transformer Variants

BERT: Encoder-only, bidirectional, great for understanding tasks

GPT: Decoder-only, autoregressive, great for generation tasks

T5: Encoder-decoder, good for both understanding and generation

Encoder vs Decoder

Understanding the differences between encoder and decoder architectures is crucial for working with sequence-to-sequence models and transformers.

Beginner Explanation

▼

Reader vs Writer Analogy:

  • Encoder = Reader: Reads and understands the input text. Like reading a book and understanding its meaning, the encoder processes input and creates a rich representation of what it means.
  • Decoder = Writer: Writes the output text based on understanding. Like writing a summary or translation, the decoder generates output word by word, using the encoder's understanding.

Key Difference: The encoder can look at the entire input at once (bidirectional), while the decoder generates output sequentially, one word at a time (autoregressive), and can only look at previously generated words.

Detailed Comparison

▼
Feature Encoder Decoder
Purpose Processes and understands input sequences Generates output sequences
Attention Types Self-attention only (bidirectional) Masked self-attention + Cross-attention
Data Flow Input → Encoder → Representation Encoder output → Decoder → Generated tokens
Processing Parallel (all tokens simultaneously) Sequential (one token at a time)
Context Bidirectional (sees past and future) Causal (only sees past tokens)
Training Objective Masked language modeling, classification Next token prediction, generation
Use Cases BERT, classification, feature extraction, Q&A GPT, text generation, translation, summarization

Architecture Differences

Encoder Architecture

  1. Input embeddings
  2. Positional encoding
  3. N × Encoder layers:
    • Multi-head self-attention
    • Feed-forward network
    • Layer normalization
    • Residual connections

Decoder Architecture

  1. Output embeddings
  2. Positional encoding
  3. N × Decoder layers:
    • Masked multi-head self-attention
    • Multi-head cross-attention
    • Feed-forward network
    • Layer normalization
    • Residual connections

Technical Deep-Dive

▼

Encoder: Bidirectional Processing

The encoder uses self-attention, meaning each token can attend to ALL tokens in the input sequence, including those that come after it. This bidirectional context is crucial for understanding tasks.

Encoder Self-Attention:
$$Attention(Q_{enc}, K_{enc}, V_{enc}) = softmax\left(\frac{Q_{enc}K_{enc}^T}{\sqrt{d_k}}\right)V_{enc}$$
Q, K, V all come from the same input sequence, allowing full bidirectional understanding

Decoder: Autoregressive Generation

The decoder uses masked self-attention to prevent looking at future tokens (since they don't exist yet during generation), and cross-attention to attend to the encoder's output.

Decoder Masked Self-Attention:
$$MaskedAttention(Q_{dec}, K_{dec}, V_{dec}) = softmax\left(\frac{Q_{dec}K_{dec}^T + M}{\sqrt{d_k}}\right)V_{dec}$$
M is a mask matrix that sets future positions to -∞ (becomes 0 after softmax)
Decoder Cross-Attention:
$$CrossAttention(Q_{dec}, K_{enc}, V_{enc}) = softmax\left(\frac{Q_{dec}K_{enc}^T}{\sqrt{d_k}}\right)V_{enc}$$
Query comes from decoder, Key/Value come from encoder - connects the two components

Mathematical Differences

The key mathematical difference is in attention computation:

  • Encoder: All-to-all attention (no masking)
  • Decoder self-attention: Causal masking (can't see future)
  • Decoder cross-attention: Decoder queries attend to encoder keys/values

Real-World Examples

▼

BERT (Encoder-Only)

Architecture: Stack of encoder layers only

Pre-training: Masked Language Modeling (MLM) - predicts masked words

Use Cases: Text classification, named entity recognition, question answering

Why encoder-only: Needs bidirectional context to understand meaning

GPT (Decoder-Only)

Architecture: Stack of decoder layers (without cross-attention to encoder)

Pre-training: Next Token Prediction - predicts next word given previous words

Use Cases: Text generation, completion, creative writing

Why decoder-only: Autoregressive generation requires causal (left-to-right) processing

T5 (Encoder-Decoder)

Architecture: Full transformer with both encoder and decoder stacks

Pre-training: Text-to-text transfer - converts all tasks to text generation

Use Cases: Translation, summarization, question answering, text classification

Why both: Encoder understands input, decoder generates structured output

Encoder

Purpose: Processes input sequences and creates rich representations

Architecture: Self-attention + Feed-forward networks

Use Cases: BERT, classification, feature extraction

Key Feature: Bidirectional context understanding

Decoder

Purpose: Generates output sequences from encoded representations

Architecture: Masked self-attention + Cross-attention + Feed-forward

Use Cases: GPT, text generation, translation

Key Feature: Autoregressive generation

Pre-training vs Fine-tuning

Pre-training learns general language patterns from large datasets, while fine-tuning adapts the model to specific tasks. This transfer learning approach has been key to modern NLP success.

Beginner Explanation

▼

Learning General Skills Then Specializing Analogy:

Imagine learning to be a doctor:

  • Pre-training = Medical School: You learn general medical knowledge - anatomy, physiology, chemistry - from thousands of textbooks and cases. This gives you a broad foundation.
  • Fine-tuning = Residency/Specialization: You then specialize in a specific area (like cardiology) with focused training on that domain. You adapt your general knowledge to the specific task.

Similarly, pre-training teaches the model general language understanding (grammar, semantics, world knowledge) from massive text datasets. Fine-tuning then adapts this general knowledge to specific tasks like sentiment analysis or question answering.

Why This Works: Most language understanding is shared across tasks. Learning general patterns once and reusing them is much more efficient than training from scratch for each task.

Step-by-Step: Pre-training and Fine-tuning Process

1 Pre-training: Large-Scale Learning

The model is trained on massive unlabeled text datasets (often billions of words from Wikipedia, books, web pages). The goal is to learn general language patterns, not any specific task.

Pre-training Data Examples

  • Wikipedia articles
  • Books (Project Gutenberg)
  • Web text (Common Crawl)
  • News articles

Total: Often 100+ GB of text, billions of tokens

2 Pre-training Objectives

Different models use different pre-training tasks:

BERT: Masked Language Modeling (MLM)

Randomly mask 15% of words, predict them from context. Example:

Input: "The [MASK] sat on the mat" Target: "cat"
MLM Loss:
$$L_{MLM} = -\sum_{i \in M} \log P(x_i | x_{\backslash M})$$
Predict masked tokens xᵢ given context x\M (all tokens except masked ones)

GPT: Next Token Prediction

Predict the next word given all previous words. Example:

Input: "The cat sat on" Target: "the"
Language Modeling Loss:
$$L_{LM} = -\sum_{t=1}^{T} \log P(x_t | x_{<t})$$
Predict token xₜ given all previous tokens x<ₜ
3 Fine-tuning: Task-Specific Adaptation

The pre-trained model is then fine-tuned on a smaller, labeled dataset for a specific task. The model adapts its general knowledge to the specific requirements.

Fine-tuning Process

  1. Start with pre-trained weights
  2. Add task-specific layer (if needed)
  3. Train on labeled task data
  4. Use smaller learning rate (often 10-100x smaller)
  5. Train for fewer epochs (1-10 vs 100+ for pre-training)
4 Transfer Learning Concept

Transfer learning is the key idea: knowledge learned in one context (general language) is transferred to another context (specific task). This works because:

  • Lower layers learn general features (syntax, basic semantics)
  • Higher layers learn task-specific features
  • Fine-tuning adjusts higher layers while preserving general knowledge
Transfer Learning Benefit:
$$Performance_{fine-tuned} \gg Performance_{from-scratch}$$
Fine-tuned models achieve much better performance with less data and training time
5 Result: Task-Optimized Model

After fine-tuning, the model has both general language understanding (from pre-training) and task-specific knowledge (from fine-tuning). This combination leads to superior performance.

Performance Comparison

On GLUE benchmark (language understanding tasks):

  • From scratch: ~60% accuracy, needs 1000s of examples
  • Fine-tuned BERT: ~80% accuracy, needs 100s of examples
  • Fine-tuned GPT-3: ~90% accuracy, sometimes zero examples!

Technical Deep-Dive

▼

Pre-training Objectives

Masked Language Modeling (BERT)

During pre-training, 15% of tokens are randomly selected:

  • 80% replaced with [MASK] token
  • 10% replaced with random token
  • 10% left unchanged

The model must predict the original token. This teaches bidirectional understanding.

Next Token Prediction (GPT)

The model predicts the next token in a sequence, learning to generate coherent text. This teaches autoregressive generation and language modeling.

Fine-tuning Strategies

1. Full Fine-tuning

Update all model parameters. Most effective but computationally expensive.

Parameter Update:
$$\theta_{new} = \theta_{old} - \alpha \nabla_{\theta} L_{task}$$
All parameters θ are updated with task-specific loss L_task

2. Parameter-Efficient Fine-tuning

LoRA (Low-Rank Adaptation): Adds small trainable matrices instead of updating all weights. Only ~1% of parameters are trained.

LoRA Update:
$$W' = W + \Delta W = W + BA$$
Only B and A matrices are trained, W remains frozen. Much more efficient!

3. Learning Rate Scheduling

Use smaller learning rates for pre-trained layers (to preserve knowledge) and larger rates for new task-specific layers. Common: 1e-5 for pre-trained, 1e-3 for new layers.

Transfer Learning Mathematics

The success of transfer learning can be understood through the lens of representation learning:

Representation Learning:
$$f_{pre-trained}: X \rightarrow Z$$
$$f_{fine-tuned}: Z \rightarrow Y_{task}$$
Pre-training learns general representation Z. Fine-tuning learns task-specific mapping from Z to Y

Retrieval Augmented Generation (RAG)

RAG combines the power of large language models with external knowledge retrieval, allowing models to access up-to-date information and domain-specific data that wasn't in their training set.

Beginner Explanation

▼

Library Analogy: Think of RAG like a research assistant who:

  • Has a general knowledge base (the LLM's training)
  • Can look up information in a library (vector database)
  • Retrieves relevant books/documents when you ask a question
  • Uses both their knowledge AND the retrieved documents to give you a complete answer

Basic RAG Concept:

Original: "My name is Paul"

Modification: "Paul is my name"

RAG Process: Query → Retrieve Context → Augment → Generate Answer

Instead of relying solely on what the model learned during training, RAG allows the model to "look up" relevant information from external sources and use that to generate more accurate, up-to-date responses.

Step-by-Step: How RAG Works

1 User Query

A user asks a question or provides a prompt. This query will be used both to retrieve relevant information and to generate the final answer.

Query: "What are the latest developments in quantum computing?"

2 Query Embedding

The query is converted into a vector (embedding) using the same embedding model used to index the documents. This allows semantic similarity search.

Query Embedding:
$$q_{embed} = Embedding(query)$$
3 Retrieval from Vector Database

The query embedding is compared against all document embeddings in the vector database using similarity metrics (like cosine similarity). The top-K most relevant documents are retrieved.

Similarity Calculation:
$$similarity(q, d) = \frac{q \cdot d}{||q|| \times ||d||}$$
Cosine similarity between query vector q and document vector d
4 Augmentation

The retrieved documents are combined with the original query to create an augmented prompt. This prompt includes context that the LLM can use to generate a more informed answer.

Augmented Prompt Structure:

# Context from retrieved documents Context: [Retrieved document 1] [Retrieved document 2] [Retrieved document 3] # Original query Question: {user_query} # Instruction Answer: [LLM generates answer using context]
5 Generation

The LLM generates a response using both its pre-trained knowledge and the retrieved context. This results in answers that are more accurate, up-to-date, and grounded in the provided documents.

Final Output

The LLM produces a comprehensive answer that combines:

  • General knowledge from pre-training
  • Specific information from retrieved documents
  • Contextual understanding of the query

Technical Deep-Dive

▼

RAG Architecture Overview

RAG consists of two main phases:

  1. Data Ingestion Phase: External knowledge sources are processed, chunked, embedded, and stored in a vector database
  2. Retrieval Phase: User queries trigger retrieval of relevant documents, which are then used to augment the LLM's generation

RAG vs Traditional LLM

Feature Traditional LLM RAG
Knowledge Source Only training data (static) Training data + External documents (dynamic)
Up-to-date Info Limited to training cutoff date Can access latest information
Domain-Specific Limited to training domain Can use domain-specific documents
Hallucination Higher risk Lower risk (grounded in retrieved docs)
Transparency Black box Can cite sources (retrieved documents)

Mathematical Formulation

RAG Generation:
$$P(y|x) = \sum_{z \in Z} P(z|x) \times P(y|x,z)$$
Where x is the query, y is the generated answer, z are retrieved documents from set Z. RAG retrieves documents z and conditions generation on both x and z.

Examples & Use Cases

▼

Question Answering

RAG excels at answering questions about specific documents or knowledge bases. The model can retrieve relevant passages and synthesize an answer.

Chatbots with Company Knowledge

Internal company documents can be indexed, allowing chatbots to answer questions about company policies, products, or procedures using RAG.

Research Assistance

RAG can help researchers by retrieving relevant papers or documents and generating summaries or answers based on the latest research.

LLM Problems & Limitations

Understanding the limitations of Large Language Models helps explain why RAG is necessary. LLMs face several critical challenges that RAG addresses.

Why RAG Exists

▼

Large Language Models are incredibly powerful, but they have fundamental limitations that make them unsuitable for many real-world applications without augmentation:

  • They only know what was in their training data
  • They can't access information after their training cutoff date
  • They don't have access to private or domain-specific data
  • They sometimes "hallucinate" or make up information
  • Training them is extremely expensive

RAG solves these problems by giving LLMs access to external knowledge sources at inference time, without requiring expensive retraining.

Detailed Problem Breakdown

▼

1. Knowledge Cutoffs

Problem: LLMs have a training cutoff date. They don't know about events, discoveries, or information that occurred after this date.

Example: GPT-3.5 was trained on data up to September 2021. It doesn't know about events in 2022, 2023, or 2024.

RAG Solution: By indexing up-to-date documents, RAG can provide current information even if the base model is outdated.

2. Lack of Domain-Specific Information

Problem: General LLMs may not have deep knowledge in specialized domains like medicine, law, or specific industries.

Example: Asking about a specific company's internal processes or proprietary technology.

RAG Solution: Index domain-specific documents, research papers, or knowledge bases to provide expert-level information.

3. Lack of Private Data

Problem: LLMs can't access private, confidential, or proprietary information that wasn't in their training data.

Example: Customer data, internal reports, confidential documents.

RAG Solution: Index private documents in a secure vector database, allowing the LLM to access them without exposing them in training.

4. Loss of Trusted Sources

Problem: LLMs mix information from various sources during training, making it impossible to verify or cite sources.

Example: Can't tell if information came from Wikipedia, a blog, or a research paper.

RAG Solution: Retrieved documents can be cited, allowing users to verify sources and trust the information.

5. Probabilistic Output / Hallucination

Problem: LLMs generate text probabilistically and can "hallucinate" - make up information that sounds plausible but is incorrect.

Example: Creating fake citations, making up statistics, or inventing facts.

RAG Solution: By grounding generation in retrieved documents, RAG reduces hallucination and produces more factual outputs.

6. Computational Expense

Problem: Training large language models requires massive computational resources, GPUs, and time. Updating them with new information means retraining.

Example: Training GPT-3 cost millions of dollars and required thousands of GPUs for weeks.

RAG Solution: No retraining needed. Simply add new documents to the vector database. Much cheaper and faster to update.

RAG Architecture

RAG follows a two-phase architecture: Data Ingestion (offline) and Retrieval-Augmented Generation (online). Understanding this architecture is key to implementing effective RAG systems.

Beginner Explanation

▼

Two-Phase System:

  • Phase 1 - Data Ingestion (Setup): Like organizing a library. Documents are processed, indexed, and stored so they can be quickly found later.
  • Phase 2 - Retrieval (Runtime): Like using the library. When someone asks a question, you find relevant books and use them to answer.

The key insight is that expensive processing (embedding generation, indexing) happens once during setup, while fast retrieval happens every time a query comes in.

RAG Architecture: Two Phases

1 Phase 1: Data Ingestion - Document Collection

External knowledge sources are collected. These can be PDFs, web pages, databases, or any text-based documents that contain information you want the system to access.

Data Sources

  • Documents: PDF, HTML, JSON, CSV, XLSX, DOCX, PPTX
  • Images: JPG, PNG, GIF, TIF
  • Multimodal: Audio, Video
2 Phase 1: Data Ingestion - Chunking

Documents are split into smaller chunks. This is important because:

  • LLMs have context length limits
  • Smaller chunks allow more precise retrieval
  • Enables retrieving only relevant portions

Chunking Strategies

Common approaches: Fixed-size chunks, sentence-based chunks, semantic chunks (grouping related sentences)

3 Phase 1: Data Ingestion - Embedding & Storage

Each chunk is converted to a vector (embedding) using an embedding model. These embeddings are stored in a vector database, creating a searchable index.

Embedding Process:
$$chunk \rightarrow EmbeddingModel \rightarrow vector \rightarrow VectorDB$$
4 Phase 2: Retrieval - Query Processing

When a user query arrives, it's converted to an embedding using the same model. This query embedding is used to search the vector database for similar document chunks.

Retrieval Process:
$$query \rightarrow EmbeddingModel \rightarrow query_{vector} \rightarrow VectorDB_{search}$$
5 Phase 2: Retrieval - Augmentation & Generation

Retrieved chunks are combined with the query to create an augmented prompt. The LLM generates a response using both its pre-trained knowledge and the retrieved context.

Complete Flow

Query (Q) + Retrieved Documents (R) + Prompt Template (P) → LLM → Answer

Technical Deep-Dive

▼

Complete RAG Pipeline

# Phase 1: Data Ingestion (Offline) def ingest_documents(documents): chunks = chunk_documents(documents) embeddings = embedding_model.encode(chunks) vector_db.add(embeddings, chunks) # Phase 2: Retrieval & Generation (Online) def rag_query(query): # Retrieve query_embedding = embedding_model.encode(query) retrieved_docs = vector_db.search(query_embedding, top_k=5) # Augment prompt = build_prompt(query, retrieved_docs) # Generate answer = llm.generate(prompt) return answer

Data Ingestion Phase

The data ingestion phase prepares external knowledge sources for efficient retrieval. This offline process transforms raw documents into searchable vector representations.

Beginner Explanation

▼

Library Organization Analogy: Before you can quickly find books in a library, someone needs to:

  1. Collect all the books
  2. Read and understand what each book is about
  3. Create a catalog/index system
  4. Organize books on shelves

Data ingestion does the same for documents: it processes them, understands their content (via embeddings), and organizes them in a searchable database.

Document Crawling & Processing

Documents need to be:

  1. Crawled/Collected: Retrieved from sources (web scraping, file systems, APIs)
  2. Parsed: Extracted from their native format (PDF parsing, HTML parsing)
  3. Cleaned: Remove noise, format text consistently
  4. Validated: Ensure quality and relevance

Chunking Strategies

1. Fixed-Size Chunking

Split text into chunks of fixed character/token count. Simple but may break sentences.

2. Sentence-Based Chunking

Split at sentence boundaries. Preserves semantic units better.

3. Semantic Chunking

Group related sentences based on semantic similarity. Most sophisticated approach.

Embedding Generation

Each chunk is converted to a dense vector using an embedding model. The same model must be used for both ingestion and retrieval to ensure compatibility.

Embedding Process:
$$embedding = EmbeddingModel(chunk)$$
Typically produces vectors of 384, 512, or 768 dimensions

Vector Database Storage

Embeddings are stored in a vector database along with:

  • Original text chunks
  • Metadata (source, timestamp, etc.)
  • Indexes for fast similarity search

Vector Databases

Vector databases are specialized databases designed to store and efficiently search high-dimensional vectors (embeddings). They enable fast similarity search, which is crucial for RAG retrieval.

Beginner Explanation

▼

Number Representation: Just as words can be represented as numbers, entire documents can be represented as vectors (lists of numbers).

Example: Text to Vector

Text: "My name is Paul"

Vector: [0.1, 0.8, 0.9, 0.75, ...] (typically 384-768 numbers)

Vector Database: A special database optimized for finding similar vectors. When you search with a query vector, it quickly finds the most similar document vectors, even from millions of documents.

Technical Deep-Dive

▼

What Are Vector Databases?

Unlike traditional databases that search by exact matches or keywords, vector databases use similarity metrics (like cosine similarity) to find semantically similar content. This enables semantic search - finding documents that mean similar things, even if they use different words.

How Vector Search Works

Vector databases use specialized indexing algorithms to enable fast similarity search:

  • Inverted File Index (IVF): Groups similar vectors together
  • Product Quantization (PQ): Compresses vectors for faster search
  • Hierarchical Navigable Small World (HNSW): Graph-based approximate search

Embeddings

Embeddings convert text (or other data) into dense vector representations that capture semantic meaning. Different embedding algorithms serve different purposes in RAG systems.

Beginner Explanation

▼

What are Embeddings? Embeddings are numerical representations of text that capture meaning. Words or sentences with similar meanings have similar embeddings (vectors that are close together in high-dimensional space).

Simple Analogy

Think of embeddings like coordinates on a map. Words that mean similar things are placed close together. "Cat" and "kitten" would be neighbors, while "cat" and "airplane" would be far apart.

This allows computers to understand semantic relationships - finding documents that mean similar things, even if they use different words.

Embedding Algorithms

▼

1. One-Hot Encoding

Description: Each word gets a unique binary vector with a single 1 and all other positions 0. Simple but doesn't capture relationships.

# Vocabulary: ["cat", "dog", "bird"] "cat" → [1, 0, 0] "dog" → [0, 1, 0] "bird" → [0, 0, 1]

Limitation: Vectors are orthogonal - no semantic similarity captured

2. TF-IDF (Term Frequency-Inverse Document Frequency)

Description: Weights words by how important they are in a document relative to the corpus. Common words get lower weights.

TF-IDF Formula:
$$TF\text{-}IDF(t,d) = TF(t,d) \times IDF(t)$$
$$IDF(t) = \log\frac{N}{df(t)}$$
Where N is total documents, df(t) is documents containing term t

Use Case: Good for keyword-based search, sparse vectors

3. Co-occurrence Matrix & CBOW

Co-occurrence Matrix: Counts how often words appear together in context windows. Words that co-occur frequently are likely related.

CBOW (Continuous Bag of Words): Predicts a word from its context. Trains a neural network to learn word embeddings.

CBOW Objective:
$$P(w_t | w_{t-k}, ..., w_{t+k})$$
Predicts center word wₜ given surrounding context words

4. Word2Vec - Skip-gram

Description: Predicts context words from a center word. Inverse of CBOW. Often performs better for rare words.

Skip-gram Objective:
$$P(w_{t-k}, ..., w_{t+k} | w_t)$$
Predicts surrounding context words given center word wₜ

Result: Dense vectors (typically 100-300 dimensions) that capture semantic and syntactic relationships

5. Positional Encoding

Description: Adds position information to embeddings. Critical for transformers to understand word order.

Positional Encoding:
$$PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$
$$PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

Use Case: Combined with word embeddings in transformer models

6. ELMO (Embeddings from Language Models)

Description: Uses bidirectional LSTM to create context-aware embeddings. Same word gets different embeddings based on context.

Innovation: First major contextualized embedding model. "Bank" in "river bank" vs "money bank" gets different embeddings.

Limitation: Replaced by transformer-based models (BERT, etc.) which are more efficient and effective

Modern Embedding Models

Model Type Dimensions Use Case

Text, Image, and Numeric Representations

Embeddings aren't limited to text:

  • Text: Sentence transformers, word embeddings
  • Images: Vision models (CLIP, ResNet) create image embeddings
  • Numeric: Can be embedded directly or through learned representations
  • Multimodal: Models like CLIP create joint text-image embeddings

Embedding Evaluation

Models are evaluated using benchmarks like MTEB (Massive Text Embedding Benchmark) which tests various tasks:

  • Semantic similarity
  • Clustering
  • Classification
  • Retrieval

Retrieval Mechanisms

Retrieval is the process of finding relevant documents from the vector database given a query. Different retrieval strategies balance accuracy, speed, and computational cost.

Beginner Explanation

▼

Finding Similar Documents: When you ask a question, the system needs to find documents that are most relevant. It does this by:

  1. Converting your question into a vector (embedding)
  2. Comparing this vector to all document vectors in the database
  3. Finding the most similar ones (using similarity metrics)
  4. Returning the top-K most relevant documents

Think of it like a librarian who understands the meaning of your question and finds books that discuss similar topics, even if they use different words.

Retrieval Process

1 Query Embedding

The user query is converted to an embedding using the same embedding model used during data ingestion. This ensures compatibility for similarity comparison.

Query Embedding:
$$q_{embed} = EmbeddingModel(query)$$
2 Similarity Calculation

The query embedding is compared against all document embeddings using cosine similarity. This measures the angle between vectors, indicating semantic similarity.

Cosine Similarity:
$$similarity(q, d) = \frac{q \cdot d}{||q|| \times ||d||} = \cos(\theta)$$
Returns value between -1 and 1. Higher values mean more similar.
3 Ranking & Selection

Documents are ranked by similarity score. The top-K documents (typically 3-10) are selected as the most relevant for the query.

Top-K Retrieval

Common values: K=3 for focused answers, K=5-10 for comprehensive coverage

4 Document Retrieval

The original text chunks corresponding to the top-K embeddings are retrieved. These will be used to augment the prompt for the LLM.

Result

Returns: [Document 1 text, Document 2 text, ..., Document K text]

Technical Deep-Dive

▼

Neural Retriever: DPR (Dense Passage Retrieval)

DPR: A neural retrieval system that uses two separate encoders:

  • Passage Encoder: Encodes document passages into vectors
  • Question Encoder: Encodes questions/queries into vectors

Both encoders are trained jointly to maximize the similarity between relevant question-passage pairs.

Bi-Encoders

Architecture

Bi-encoders use two separate encoders:

# Passage Encoder p_embed = PassageEncoder(passage) # Question Encoder q_embed = QuestionEncoder(question) # Similarity similarity = cosine_similarity(q_embed, p_embed)

Advantage: Efficient - embeddings can be pre-computed and stored. Fast at inference time.

Cosine Similarity

Cosine Similarity Formula:
$$\cos(\theta) = \frac{\mathbf{q} \cdot \mathbf{d}}{||\mathbf{q}|| \times ||\mathbf{d}||} = \frac{\sum_{i=1}^{n} q_i d_i}{\sqrt{\sum_{i=1}^{n} q_i^2} \times \sqrt{\sum_{i=1}^{n} d_i^2}}$$
Measures the cosine of the angle between two vectors. Range: [-1, 1]. Higher values indicate greater similarity.

Why Cosine Similarity? It's scale-invariant - focuses on direction rather than magnitude, which is ideal for semantic similarity.

Dense Vectors vs Sparse Vectors

Type Description Use Case
Dense Vectors Most values are non-zero, captures semantic meaning Semantic search, neural retrieval
Sparse Vectors Most values are zero (e.g., TF-IDF, BM25) Keyword-based search, exact matching

Semantic Similarity

Unlike keyword matching, semantic similarity finds documents that mean similar things, even with different words:

Example

Query: "How do I reset my password?"

Can match: "Password recovery instructions", "Account access reset", "Forgot password guide" - even without exact word matches

Ranking Retrieved Documents

After similarity calculation, documents are ranked and filtered:

  • Similarity Score: Primary ranking factor
  • Re-ranking: Optional second-stage ranking using more sophisticated models
  • Diversity: May filter to ensure diverse document coverage
  • Relevance Threshold: Filter out low-similarity documents

Augmentation

Augmentation combines the user query with retrieved documents to create a context-rich prompt for the LLM. Effective prompt construction is crucial for high-quality RAG outputs.

Beginner Explanation

▼

Building Context: Augmentation is like giving a student both the question AND relevant reference materials before they write an essay. Instead of relying only on memory, they can use the provided documents to give a more accurate answer.

The augmented prompt contains three key parts:

  • Q (Query): The user's original question
  • R (Retrieved Documents): Relevant context from the vector database
  • P (Prompt Template): Instructions telling the LLM how to use the context

Technical Deep-Dive

▼

Prompt Construction

The augmented prompt follows a structured format:

# Standard RAG Prompt Template Context: {retrieved_document_1} {retrieved_document_2} {retrieved_document_3} Question: {user_query} Instruction: Answer the question using only the information provided in the context above. If the answer cannot be found in the context, say "I don't have enough information to answer this question." Answer:

Context Assembly (Q + R + P)

Components

Q (Query): The original user question or prompt

R (Retrieved Documents): Top-K most relevant documents from vector search

P (Prompt Template): Instructions, formatting, and guidelines for the LLM

Prompt Engineering Best Practices

1. Clear Instructions

Explicitly tell the LLM to use only the provided context and cite sources when possible.

2. Context Ordering

Place most relevant documents first. Some models pay more attention to earlier context.

3. Length Management

Balance context length with model limits. Too much context can dilute important information.

4. Formatting

Use clear separators, headers, and structure to help the LLM parse the context effectively.

Advanced Prompting Techniques

  • Few-shot Examples: Include example Q&A pairs in the prompt
  • Chain-of-Thought: Ask the LLM to reason step-by-step
  • Self-Consistency: Generate multiple answers and select the most consistent
  • Citation Requirements: Ask the LLM to cite which document it used

Extractive vs Abstractive Generation

RAG systems can generate answers in two ways: extractive (copying exact text) or abstractive (synthesizing new text). Each approach has different strengths and use cases.

Beginner Explanation

▼

Extractive: Like highlighting a sentence in a book - you find the exact piece of information and present it as-is.

Abstractive: Like writing a summary - you understand the information and rephrase it in your own words, potentially combining multiple sources.

Technical Deep-Dive

▼

1. Extractive Generation

Definition: Returns the exact same piece of information from the retrieved documents, without modification.

# Example Query: "What is the capital of France?" Retrieved Document: "Paris is the capital and largest city of France." Extractive Answer: "Paris is the capital and largest city of France."

Advantages: Accurate, preserves original wording, no hallucination risk

Disadvantages: May be verbose, doesn't synthesize information

2. Abstractive Generation

Definition: Modified information with the same context, like rephrasing or synthesizing from multiple sources.

# Example Query: "What is the capital of France?" Retrieved Documents: - "Paris is the capital and largest city of France." - "Paris has been France's capital since 987 AD." Abstractive Answer: "The capital of France is Paris, which has served as the country's capital since 987 AD and is also its largest city."

Advantages: More concise, can synthesize multiple sources, natural language

Disadvantages: Risk of hallucination, may introduce errors

Comparison

Feature Extractive Abstractive
Output Exact text from documents Rephrased/synthesized text
Accuracy Very high (no modification) High (but can introduce errors)
Conciseness May be verbose More concise
Multi-source Limited Can synthesize multiple sources
Use Case Factual Q&A, citations Summaries, explanations

When to Use Each

Use Extractive When:

  • Exact wording matters (legal, medical)
  • Citations are required
  • Minimizing hallucination risk is critical
  • Simple factual questions

Use Abstractive When:

  • Need to synthesize multiple sources
  • Want concise, natural language answers
  • Creating summaries or explanations
  • User experience prioritizes readability

Parametric vs Non-Parametric Memory

Understanding the difference between parametric and non-parametric memory helps explain how RAG extends LLM capabilities. Traditional LLMs use parametric memory, while RAG adds non-parametric memory.

Beginner Explanation

▼

Two Types of Memory:

  • Parametric Memory: Knowledge stored in the model's weights. Like memorizing facts - once learned, it's part of the model forever (until retraining).
  • Non-Parametric Memory: Knowledge stored externally (like in a database). Like having a reference library - you can add new books without changing your brain.

RAG combines both: the model's parametric memory (general knowledge) with non-parametric memory (external documents) to provide comprehensive answers.

Technical Deep-Dive

▼

Parametric Memory

How It Works

Knowledge is encoded in the model's weights/parameters during training. For example, a pretrained Seq2Seq model like BART (400M parameters) stores knowledge in its weights.

Parametric Knowledge:
$$Knowledge \in Model_{weights}$$
Training Data → Model Parameters → NLP Tasks

Characteristics:

  • Fixed at training time
  • Requires retraining to update
  • Limited by model size
  • Fast access (no external lookup)

Non-Parametric Memory

How It Works

Knowledge is stored as dense vectors in external data sources (vector databases). Accessed via Neural Retriever (like DPR - Dense Passage Retrieval).

Non-Parametric Knowledge:
$$Knowledge \in External_{VectorDB}$$
External Data Sources → Vector Index → Retrieved via Similarity Search

Characteristics:

  • Dynamic - can be updated without retraining
  • Unlimited size (scales with storage)
  • Requires retrieval step (slower)
  • Can include latest information

Comparison

Feature Parametric Memory Non-Parametric Memory
Storage Model weights External vector database
Update Requires retraining Add to database
Size Limit Model capacity Storage capacity
Access Speed Instant (inference) Requires search
Example BART 400M parameters Wikipedia indexed in vector DB

Hybrid Approach: RAG

RAG combines both memory types:

  • Parametric: General language understanding, reasoning, generation capabilities
  • Non-Parametric: Specific facts, up-to-date information, domain knowledge

This hybrid approach gives the best of both worlds: the model's learned capabilities plus access to external, updatable knowledge.

RAG Recipes

Different RAG implementations use different strategies for how retrieved documents are used during generation. The two main recipes are RAG Sequence and RAG Token.

Beginner Explanation

▼

Two Approaches:

  • RAG Sequence: Like writing an essay using the same set of reference books throughout. You retrieve documents once and use them for the entire answer.
  • RAG Token: Like consulting different books for different parts of your essay. You can retrieve different documents for different parts of the generated answer.

Technical Deep-Dive

▼

1. RAG Sequence

Definition: Uses the same retrieved documents to generate the entire output sequence. Documents are retrieved once at the beginning.

# RAG Sequence Flow query = "Explain quantum computing" retrieved_docs = retrieve(query, top_k=5) # Retrieved once prompt = build_prompt(query, retrieved_docs) answer = llm.generate(prompt) # Uses same docs for entire generation

Advantages: Simple, efficient, consistent context

Use Case: Single-topic questions, focused answers

2. RAG Token

Definition: Can use different documents to generate different parts of the final output sequence. Documents can be retrieved multiple times during generation.

# RAG Token Flow query = "Compare quantum and classical computing" # Can retrieve different docs for different parts quantum_docs = retrieve("quantum computing", top_k=3) classical_docs = retrieve("classical computing", top_k=3) # Generate answer using different docs for different sections answer = generate_with_multiple_contexts(query, quantum_docs, classical_docs)

Advantages: More flexible, can handle multi-faceted questions, better for long answers

Use Case: Complex questions requiring multiple sources, comparative answers

Comparison

Feature RAG Sequence RAG Token
Retrieval Once at start Multiple times during generation
Documents Used Same docs for entire output Different docs for different parts
Complexity Simpler More complex
Efficiency More efficient Less efficient (multiple retrievals)
Flexibility Limited High
Best For Focused, single-topic answers Complex, multi-faceted questions

Implementation Differences

RAG Sequence Implementation

# Single retrieval, single generation docs = retrieve(query) prompt = f"Context: {docs}\nQuestion: {query}\nAnswer:" answer = llm.generate(prompt)

RAG Token Implementation

# Multiple retrievals, adaptive generation for token in generate_tokens(): if needs_new_context(token): docs = retrieve(generate_subquery(token)) prompt = build_prompt(token, docs) next_token = llm.generate_token(prompt)
